# 程序化诗境框架

## 这一阶段的范围

先建立一处可以完整运行、暂停、恢复和释放的诗境，再扩展作品集。首景仍在视觉打磨阶段，具体意象是寒日庭院中的雪与风；庭院建筑属于视觉演绎，不声称复原某一处历史建筑。几何、表面、倒影、环境光和声音均由运行时程序生成。

## 子系统契约

| 模块 | 拥有的状态 | 不应承担的职责 |
| --- | --- | --- |
| `WeatherSimulation` | 活跃时间、阵风、雪量 | Three.js 对象、浏览器权限、DOM |
| `PoemScene` | 自己创建的几何、材质、粒子和场景缓存 | 全局循环、窗口事件、AudioContext |
| `WorldRenderer` | Renderer、相机、光照、雾、环境图、接地遮蔽与帧诊断 | 诗文内容、用户声音意图 |
| `ProceduralPond` | Reflector、反射缓存、解析水面与失效状态 | 独立计时器、窗口事件、全局渲染循环 |
| `ProceduralAmbience` | 懒创建的 AudioContext、图、播放意图 | 浏览器 visibility 监听、场景几何 |
| `Shell` | DOM、原文与设置对话框 | 绘制循环、材质生成、音频 DSP |
| `main` | 输入映射、组合暂停原因、资源装配 | 各诗境具体几何和声音采样算法 |

长度以米、时间以秒计，+Y 向上。相机采用受控小范围观看；此版没有碰撞或自由行走系统，因此没有引入物理引擎。

雪庭由 `geometry.ts` 装配；`courtyardArchitecture.ts` 生成廊屋、月门砖圈、屋面与半筒瓦，`winterTree.ts` 生成连续主干、分级枝系与枝上积雪，`ProceduralPond.ts` 管理池面及其反射。树皮使用独立的程序化 `bark` 材质，与建筑木料的表面参数分开。

## 程序生成与缓存

1. 使用 `seed + namespace` 为每个系统生成独立随机序列。
2. 初次进入场景时生成几何与粒子分布。静态几何按材质实例、投影属性和图层合并，减少绘制调用；主树保留独立变换以随风摆动，水面也单独保留。需要独立控制可见性或变换的子树必须排除合并。
3. 材质函数以米制表面坐标解析计算颜色、粗糙度与微表面变化，细节随移动网格一起运动；高度与接地计算仍使用世界坐标。颜色在 Three.js 的线性光照流程中运算，输出统一做色调映射与色彩转换。
4. 天空是着色器，PMREM 在启动／上下文恢复时由该天空生成。环境图作为运行时缓存由 Renderer 释放。
5. 启动／上下文恢复时，从近地几何下方捕获随高度衰减的遮蔽场，模糊并缓存。接收权重写入顶点属性，仅让不投射、但接收阴影的地面采样它；共用雪材质的石阶和石块雪帽不会采样自身投影而变黑。这是一种局部地面遮蔽近似，不能替代全局光照或实时树影。画质切换和逐帧更新不重新捕获。
6. 池面使用 Three.js `Reflector` 捕获当前场景的平面倒影，再解析计算涟漪、岸边薄冰与霜。低／中／高画质分别使用 256²／384²／512² 反射目标；目标保持线性 HDR，水面着色器统一完成色调映射与显示色彩转换。反射不依赖预制图像。
7. 显式开启声音时才生成 PCM 与音频图；逐帧只更新平滑参数。风声使用周期稳态滤波，避免循环尾部被人为抹平而出现周期性变弱；两路不同长度的风声和一路不规则木构共振构成固定三个循环声源。共享风场同时驱动滤波、声像与播放速率。

池面读取同一份 `EnvironmentSnapshot`，没有第二套时钟。视角静止时，反射按模拟时间每 1/8 秒刷新，其余帧复用缓存；相机、投影或池面变换变化会提前刷新。雪量变化、时间回退、反射尺寸变化和 `invalidateRenderCaches()` 会让下一次绘制重新捕获。暂停时模拟时间不推进，静止画面不会为反射继续计时。

`WorldRenderer` 在一次可见帧开始前统一重置统计，`calls`／`triangles` 包含嵌套反射绘制。场景另提供 `reflectionUpdates`／`reflectionSize`，比较渲染开销时应区分反射刷新帧与缓存复用帧，不能把这些指标直接等同于真实设备 FPS。

当前逐像素材质计算的成本需在实机上评估。后续可以把相同函数按需烘到**运行时生成**的 GPU 纹理中缓存，并保持无预制素材原则。大规模几何／声音生成时，再按真实耗时引入分帧或 Worker。

## 时间与暂停

- `requestAnimationFrame` 只负责调度，模拟按秒推进。
- 首帧 delta 为零；长帧最大推进 0.1 秒，避免页面恢复时跳变。
- 画质、雪量与窗口尺寸先更新状态，静止画面的重绘合并到下一帧；活动动画循环会负责自己的重绘。这样不在输入事件处理器中同步编译新的渲染变体，恢复播放和退出时也会取消待执行的静态帧。
- 用户暂停、页面隐藏、对话框打开、上下文丢失采用组合条件；任何一项成立就暂停画面。声音使用独立组合条件：设置弹窗允许试听已开启的声音，诗文弹窗仍暂停声音。
- 恢复时清空上一帧时间戳，不追赶后台时间。
- 原生 AudioContext 的启用意图与临时暂停状态分离；暂停不覆盖声音开关。
- 用户主动起风可以从静止状态开始体验。
- WebGL 恢复时重建环境光与接地遮蔽，并通过场景的 `invalidateRenderCaches()` 使池面反射在下一次绘制刷新。
- 应用的恢复监听器先于 Three.js 注册，因此必须等到下一个任务再重建 GPU 缓存。原生事件监听器之间可能执行微任务，仅 `await Promise.resolve()` 无法保证 Three.js 已完成内部恢复；浏览器回归检查会比较静止画面恢复前后的颜色。
- 池面反射目标由 `disposeTargets()` 释放；其几何与材质由场景遍历统一释放，避免重复调用会同时释放材质的 `Reflector.dispose()`。

## 新增一首诗

1. 校对诗文、出处、季节与所要表现的意象。
2. 在 `scenes/<id>/` 实现 `PoemScene`。模块内部应显式拥有生成的资源，并完整 `dispose()`；有生成缓存时实现可选的 `invalidateRenderCaches()`，需要观测场景开销时提供 `diagnostics()`。
3. 提供适配横竖屏的小范围相机位置与目标点。
4. 在 `registry.ts` 注册内容和创建函数。作品数量增加后再设计选择界面。
5. 让风、雨或其他声音读取共同的环境状态；需要新的状态字段时扩展 `core/types.ts`。
6. 给生成器添加有价值的边界测试，并在浏览器中验证真实画面和声音状态。

## 后续美术优先级

- 地面与屋顶积雪需要更多由几何朝向、遮挡和风向决定的厚度变化。
- 改善树木枝形、自然石块表面、瓦片与建筑尺度关系。
- 逐景调整相机、远近层次和光照；保持原文意境。
- 在真实手机上测量帧耗时、发热、启动时间，决定是否增加自动画质适配。
- 用真实耳机／扬声器检查风声循环、频谱、响度与画面的一致性。

这些是后续可独立推进的工作，不应在首个框架中提前加入账号、社交、计分或通用编辑器。
