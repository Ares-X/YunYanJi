# 架构

## 范围与模块边界

当前注册的场景是 `rainfire`，由 `createRainfireWorld` 创建。项目从古诗雪景转向独处的自然风景，复用时间、GPU 生命周期和音频管理，雨林与地表使用独立生成器，不继续扩展原有诗境选目。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `WeatherSimulation` | 种子、模拟时间、六种天候、阵风、降水和雷电事件 | Three.js 对象、DOM 和浏览器权限 |
| `CampfireSimulation` | 燃料、五种火势、余烬、烟和添柴事件 | GPU 几何、音频节点与独立时钟 |
| `LandscapeScene` | 自有几何、材质、相机基准、更新、画质和释放 | 全局事件、音频授权和动画循环 |
| `WorldRenderer` | 相机、主灯光、环境、画质、GPU 提交与恢复 | 推进天气时间、创建音频节点 |
| `RainAtmosphere` / `weatherLighting` | 解析天空、云量、昼光、闪光和共享照明参数 | 独立计时、固定天空图片 |
| `ForestEnvironment` | 先生成天空环境，再捕获林木、地面与布棚的局部环境辐射 | 动态全局光照和实时反射追踪 |
| `GroundContactShadows` | 共享的近地接触遮蔽捕获、接收标记与缓存 | 全局光照和动态物体的逐帧阴影 |
| `SurfaceOcclusion` | 独立不透明深度、GTAO 去噪和材质中的间接光遮蔽 | 火光直接照明、全局光照和反射相机的 AO |
| `CanopyLightField` | 静止姿态的树冠／布棚覆盖，供间接照明与空气散射共同采样 | 逐叶动态阴影、直接光衰减和全局光照求解 |
| `ForestAtmospherePass` | 根据独立不透明深度积分受光湿雾，采样树冠场与方向／火光阴影 | 重新绘制场景深度、独立推进时间 |
| `LandscapePostProcessing` | 编排深度／间接 AO、PBR 画面、受光湿雾、HDR 辉光与输出转换 | 场景生成、调度 RAF |
| `ProceduralAmbience` | 用户开启意图、AudioContext、暂停与释放 | 直接读取 DOM 和推进天气 |
| `createAmbienceGraph` / `AmbienceEventCursor` | 合成声源、空间混音、参数平滑、按模拟时间触发短事件与有界释放 | 新建计时器、下载录音 |
| `Shell` / `main` | 原生界面、交互、组合暂停原因和系统装配 | 具体地形及合成声音算法 |

米与秒是统一单位，+Y 向上。视觉和声音读取同一份 `EnvironmentSnapshot`：`weather` 包含天候、雨量、雪量、云量、昼光与薄雪覆盖，`lightning` 包含雷电身份、年龄、距离、声传播延迟和闪光强度，`fire` 包含燃料、热量、火焰、余烬、烟与添柴身份。`precipitation` 只作为液态雨量的兼容别名；雪不会生成雨圈。`elapsed`、`wind` 和 `gust` 仍由同一个模拟推进。各系统使用独立种子命名空间，新增声音随机数不会改变树的位置。

横屏、竖屏各有相机位置与目标。拖动改变受限视线并附带很小的位置偏移，不是轨道俯视，也没有自由行走或碰撞模拟。

## 天候与燃烧状态

六种天候为 `clear`、`overcast`、`drizzle`、`rain`、`downpour`、`snow`，对应晴天、阴天、小雨、大雨、暴雨与下雪。预设改变目标，运行时按秒平滑接近；暂停时直接应用可见状态，等待一次静态重绘，不暗中推进时间。「天候」是非模态面板，展开时动画和声音继续；设置弹窗仍冻结画面，并允许试听音量。

手动「打雷」与「间或雷鸣」使用同一条种子事件流，暴雨预设默认开启后者。闪光为一次快速亮起、自然衰减的宽闪，驱动天空、直接光、环境强度、雾与降水；减少动态效果偏好使闪光为零。声传播延迟为场景距离除以 343，每次新雷电必须等待上一声到达并满足最小间隔，防止连续输入盖掉尚未抵达的雷声。重置恢复种子事件流与初始火况；分享只保存世界种子，同一交互历史才会重现同一天候过程。

`CampfireSimulation` 管理熄灭、余烬、小火、中火与旺火。燃料缓慢消耗，火焰、热量与余烬按共享时间变化。添柴最多显示四根新增木柴、燃料有上限；现有木柴进入延迟着火与短暂烟气增加的过程，后续添柴复用预分配位置。给余烬添柴会转入小火；给熄灭的柴堆添柴只放入冷木柴，须选择燃烧状态才点燃。熄灭立即关闭火焰、暖光和燃烧声，残余烟气自然消退。它是供人照料的环境交互，没有生存倒计时或库存任务。

## 林间场景

| 文件 | 职责 |
| --- | --- |
| `createRainfireWorld.ts` | 装配地形、树林、地表散落物与天气效果，管理横竖屏相机和统一释放 |
| `rainLandscape.ts` | 连续高度场、破碎积水低洼、火旁高地、石块、带下垂与拉绳的布棚，以及共享的棚下范围 |
| `forestGrowth.ts` | 空间竞争、分季吸引点与枝径规则，生成连续枝冠骨架 |
| `livingForest.ts` | 成熟树干、根颈、曲线分枝、折面叶片与中远景树群，按材质及阴影范围合批 |
| `forestWind.ts` | 根部固定的树干弯曲、叶柄局部转动，以及可见／不透明深度／阴影共用的形变 |
| `barkSurface.ts` | 按物理尺度生成树皮鳞片、裂隙和苔色，共源颜色／法线／粗糙度数据 |
| `earthMaterials.ts` | 程序土壤微结构、近景起伏网格与高度采样、关联材质数据和匹配的深度裁剪，区分土壤和局部湿泥膜 |
| `forestEcology.ts` | 同一种子下的腐殖层、踩踏路径、根部影响与苔丛分布，供地表材质和几何共同采样 |
| `forestDebris.ts` | 卷曲腐叶、断枝、细砾、苔丛、蕨叶和低矮灌丛几何，按材质合批 |
| `rainMaterials.ts` | 石块、木材等表面的米制解析纹理、粗糙度和微表面法线 |
| `fireIllumination.ts` | 绝对模拟时间与种子驱动的统一燃烧包络，原位更新位置、能量、颜色及烟／炭参数 |
| `campfire.ts` | 劈柴、炭床、灰与石圈，按不透明深度截断的火舌／受光烟、冷却余烬与两处暖光 |
| `rainParticles.ts` | 雨线、落点与风驱动，读取与棚一致的遮挡范围 |
| `weatherSnow.ts` | 预分配的程序雪花、缓慢沉降与共享风偏移，按距离保持尺度并避开棚下 |
| `snowSurface.ts` | 在向上且未被棚遮蔽的表面增加斑驳薄雪着色与粗糙度；环境捕获时暂时关闭 |
| `wetGround.ts` | 浅水平面、真实场景倒影、Fresnel 与水深吸收的透明合成、细波与雨圈、反射缓存和目标所有权 |

当前树林由 `forestGrowth.ts` 生成空间竞争骨架，再由 `livingForest.ts` 转成几何。两轮吸引点生长形成不同龄枝段，按末梢数量与剩余枝长确定枝径；细枝连续着叶，叶子是有折角与弯曲的几何。近处与远处分别合批，让近处投影不必绘制整片远林。旧雪景的生成器与针叶覆盖数据仍留在归档模块，未参与活动雨林，也未注册为可选场景。

活动场景中的下雪是新增天气，不依赖归档雪景。雪覆盖通过共享 `snowCover` 缓慢积累／消退，并沿当前形变后的世界坐标与朝上法线分布；它改变表面颜色和粗糙度，没有增加雪层几何厚度、压痕或融雪流体。火堆被明确排除，棚下遮挡与雨雪粒子采用同一几何范围。

空间占据方法参考 Adam Runions、Brendan Lane、Przemyslaw Prusinkiewicz 的 [Modeling Trees with a Space Colonization Algorithm（2007）](https://algorithmicbotany.org/papers/colonization.egwnp2007.pdf)。项目使用自行实现的空间哈希、分季吸引点和方向偏置生成视觉结构，不将它作为植物生长的科学预测模型。该文献只用于开发说明，运行时不访问或下载它。

`forestWind.ts` 使用每棵树的根部／高度和每片叶子的附着位置，保持根部固定并随高度增加弯曲，叶片绕叶柄转动。主材质、`customDepthMaterial` 和 `customDistanceMaterial` 注入同一形变，主画面的法线也随之调整；独立不透明深度与方向／点光阴影使用相应的形变材质。时间读取 `EnvironmentSnapshot.elapsed`，减少动态效果模式的风形变强度为零。包围体为有界摆动留出余量，避免边缘裁剪。

树木、地表散落物和静态环境物体各自按材质、投影与接收属性合批。火组不参加通用静态合并；木柴由火模块单独合并，通过 `aFuelPosition`、`aFuelNormal`、`aFuelRadius` 和 `aFuelIdentity` 保留每段柴的原始局部坐标、法线、半径与身份，避免合批后木纹、年轮和炭化范围错位。

## 资源与运行时生成

初次进入时生成地形、树木、石块、木柴、地表散落物、粒子分布以及土壤和树皮数据，逐帧只更新必要参数。所有视觉资源来自计算；不加载固定图像贴图、HDRI、模型文件或嵌入的图像数据。程序生成的 `DataTexture`、环境纹理和渲染目标仍是正常使用的 GPU 纹理资源。

土壤把淤泥、矿物颗粒和有机残留生成到同一组微结构中，再导出关联的颜色、法线与表面数据；米制采样和不同方向的混合降低平铺痕迹。树皮由错落鳞片及裂隙高度生成关联颜色、法线和粗糙度。两者都使用运行时 `DataTexture` 和 mipmap，不从磁盘载入图像。纹理由对应材质持有，随材质释放；保留的 CPU 数据可供上下文恢复重新上传。

近景土壤用约 64,000 个三角形替换相应范围的粗地形，包含实际泥底。较粗的高度进入网格，剩余细尺度高度进入法线，避免同一层起伏被计算两次；散落物从这张三角网格回采高度。远地材质与独立深度材质使用相同的世界坐标裁剪范围，避免不可见的旧地形挡住近景。近、远土壤是独立材质实例，共享的程序纹理按引用计数释放。局部薄水膜使用物理材质的 clearcoat，法线导数补充粗糙度以减轻远处细高光闪烁。

`forestEcology.ts` 在同一种子下生成一致的 224² 分布网格，RGBA 分别表示腐殖覆盖、踩踏程度、根部影响和苔丛覆盖。CPU 双线性采样用于选择腐叶、碎枝、砾石、苔丛与蕨类位置；GPU 采样同一分布定义的运行时纹理，调整泥地色泽与细节。根部与倒木附近的腐殖区、通向火堆的踩踏区因此与表面着色有关联，而不是各系统独立撒点。该分布是场景生成规则，没有模拟植物生长、侵蚀或水流。

林下另有沿不对称土岸布置的低矮木质灌丛与蕨类，使用地形高度安放并避开积水，冠下附带腐叶与断枝。岸边残叶按实际高度寻找水线，形成小片堆积。它们复用地表叶片、木质与砾石批次，没有引入外部植物模型。

## 光场、火光与阴影

`RainAtmosphere` 计算随云量、昼光、雨雪和闪光变化的解析天空，方向光与天空共享来光方向。`weatherLighting` 为表面、天空和湿雾提供有界照明参数。启动和上下文恢复时，先烘焙地面接触场，再由 `ForestEnvironment` 捕获同一初始天气和时刻的天空作为临时照明，最后从火旁固定位置捕获林木、土壤和布棚并生成局部 PMREM。切换天气调节该探针的环境强度，同时更新实际日光和雾，不在每帧重新捕获探针。这是一处静态局部 IBL 近似，晴雨切换没有实现动态全局光照或每个物体的独立探针。

环境捕获排除粒子、透明效果、点火光和材质自发光。捕获期间将树林风形变置于时间零、强度零，暂时隐藏新增木柴和薄雪覆盖，并关闭材质额外的树冠压暗。恢复时也先使用相同初始天气照明，避免把当时的暴雨、雪或阵风重复烘入基准探针。探针使用独立的 1024² 方向光阴影，不随活动画质改变，因此切档后恢复也能重现原来的间接照明。`finally` 释放临时阴影，恢复活动阴影目标以及当前天空、照明、风与场景状态，使活动灯光阴影失效，随后重新捕获当前姿态。

`CanopyLightField` 从上方捕获同一静止姿态的树冠、树干和布棚，按覆盖率累积到 512² 目标并模糊，得到宽尺度的遮天分布。它仅在启动和环境重建时生成，不追踪每片摆动叶子。表面端只调节间接漫反射与间接镜面反射，不再乘一次直接太阳光或直接火光；普通材质的强度为 0.24、叶片为 0.14，因为局部环境已经包含森林的平均遮蔽。湿雾也采样该场，共用开敞／林冠覆盖关系。该场是二维覆盖近似，不是三维可见性场或全局光照解算。

`fireIllumination.ts` 使用连续的时间噪声组合缓慢燃料释放、气流和小尺度波动。它不推进独立 RNG 或依赖帧间滤波；同一种子、相同操作历史与共享火堆状态在同一模拟时刻得到同一组数值。稳定输出对象共同驱动火舌高度与热量、炭床和木柴裂缝、受光烟，以及分担暖光能量的两处实际点光源的位置、强度与颜色，另保留低强度余烬补光。场景通过 `fireLights` 暴露两盏灯；空气散射使用它们的合计能量与加权质心，以主灯阴影近似遮挡，没有分别积分两个灯的体积可见性，也没有形成连续面光源。

中高画质开启两处火光的点光源阴影，仅捕获指定图层、有限距离内的遮挡物；低画质关闭。木柴、石圈、近树和布棚可以遮挡火光，远林不加入这些六面捕获。地形与柴木不移动，但枝叶形变与火光位置会改变阴影：`WorldRenderer` 按模拟时间分别以最多 6 Hz 更新方向光阴影、10 Hz 更新两盏火光阴影，并分别维护灯光缓存。

完整树冠中明显超出火灯范围的三角形不再反复提交到每个点光阴影面。构建时将近景树的索引稳定分区，保守范围包含 9 米阴影立方体、0.3 米灯位变化与 1.3 米风幅；`onBeforeShadow` 仅为距离材质限制索引前缀，`onAfterShadow` 恢复原绘制范围。可见画面、不透明深度和方向光阴影仍使用完整索引，网格与绘制批次数不增加。

首次渲染、时间回退、画质切换和上下文恢复会使相应阴影缓存失效；天气和火况的 `revision` 也会使暂停时新增木柴等变化得到更新。静止重绘的 `delta === 0` 若对应时刻尚未捕获，则补一次该精确时刻的阴影；再次绘制同一暂停时刻会复用。刷新频率是缓存策略，不是测得的设备帧率，也不表示实现了动态全局照明。

`render/GroundContactShadows.ts` 是场景间共享的近地接触遮蔽实现，启动和恢复时各烘焙一次。每个顶点记录所在位置的地形高度，捕获和接收衰减使用相对当地地面的高度，使土岸上的接触不会因高于世界零点而消失。该场只补充有限高度范围内的接触感；它不是全局光照。`yyjContactGround` 明确把近、远土壤设为接收地面并排除在该场的遮挡捕获之外，不影响土壤在普通灯光中的投影；否则上视捕获会被地面自己填满。接收权重写入几何属性，保留投影与接收物共享材质时的差别；粒子和带 alpha 裁剪贴图的承载片不参与简化捕获，避免产生矩形黑块。厘米级散落物主要由屏幕空间 AO 补充接触，不逐片增加阴影绘制。

## 水面反射

浅水由水平反射面与同一连续地形相交，地形定义露出的水域边缘和火旁高地。水床平滑混向约 2–3 cm 深的浅洼，低泥脊打断部分水面，岸沿缓缓接回湿土；不从原地面固定挖出深盆。水网格以实际地形差计算深度，水线处渐隐。

Three.js `Reflector` 捕获真实场景；火焰和雨线使用相同的时间与相机协议，因此倒影来自当前场景而非另一份手画效果。水材质用 Fresnel 调节随视角变化的反射，以水深吸收控制透明层的颜色和不透明度，使下方实际渲染的泥底可见。倒影、浅水颜色与底土由透明合成叠加，水面不再完全替换泥地。

低／中／高档分别使用 256²／384²／512² 目标。视角静止时，反射通常按模拟时间最多每 1/8 秒捕获一次，其他帧复用。相机、投影、水面变换、雨量、天候／火况 revision、闪光、时间回退、目标尺寸与上下文恢复可提前使缓存失效。暂停转入精确时刻 T 时，若缓存不是 T，则补一次 T 的倒影；后续同一静止画面不重复捕获。暂停不推进模拟时间，也不为反射单独设时钟。

反射在线性 HDR 空间内完成，目标结束后恢复主渲染目标。波纹只产生细微的法线与采样扰动；棚下范围与雨线共享，不能在同一位置一边遮雨一边持续出现雨圈。

## 深度、后处理与颜色

所有画质使用同一线性颜色路径：

`独立不透明深度 → 可选 GTAO／去噪 → PBR RenderPass → ForestAtmospherePass → 可选 HDR bloom → OutputPass`

`SurfaceOcclusion` 先把不透明表面绘制到独立的 24 位深度纹理，隐藏粒子、水、火焰和其他透明效果；地形使用与可见表面一致的深度材质。中高档 GTAO 从这张深度重建法线，在半宽半高目标上计算遮蔽与边缘保持去噪，中／高档分别使用 8／16 个 AO 样本。GTAO 的 `Off` 输出模式仍执行计算，只是不把 AO 直接混到完成的图像上。

PBR 材质在合并直接光与间接光之前读取该遮蔽结果，只调整间接漫反射、间接高光和 clearcoat 间接高光。它与已有接触场取较强的遮蔽，并抵消此前应用过的接触因子，避免重复相乘造成黑边。直接火光、自发光和火焰辐射不受屏幕 AO 的整图乘暗。材质只在主相机、深度可用时启用该采样；反射与环境捕获不读取主相机的屏幕遮蔽。

火焰 raymarch 同样读取独立深度，把对应像素的不透明命中点还原到火体局部坐标，在柴木或石块之前终止积分；这不同于仅把最前一片火的深度写入片元，后者仍可能积入木柴后面的火光。发射辐射与消光分别积分。反射相机不读取主视角深度。低档保留不透明深度捕获和火焰遮挡，只跳过 GTAO／去噪。

`ForestAtmospherePass` 显式持有 `SurfaceOcclusion.depthField.texture`，以同一相机的不透明命中深度截断沿视线的单次散射和透射率积分，不从 composer 当前颜色缓冲推断深度。程序 32³ 噪声形成近地湿雾，时间来自共享模拟；固定主风向的连续漂移与有界阵风位移组合，避免运行时间乘瞬时风速造成跳变。中高档在半宽半高目标使用 18／28 个样本，低档在宽高各 35% 的目标使用 10 个样本。采用固定的逐像素哈希采样扰动，再对散射／透射做两次保持深度边界的空间去噪；不模糊原场景颜色。上采样同样用深度差约束邻近样本，减少远处亮雾污染近树边缘。中高档查询已有方向光和主火光阴影；低档保留覆盖场与深度积分，省略逐样本阴影查询。在线性空间以「表面颜色 × 透射率 + 散射光」合成。

独立深度不包含水、火焰等透明层；它们与最终湿雾的组合是实时近似。场景自身保留较轻的远距雾，也会进入浅水反射；依赖当前视线的受光湿雾只在最终主画面执行一次，没有为每次反射另外计算体积雾，也没有实现多次散射或完整水汽模拟。

主画面写入 HalfFloat HDR 与自己的深度目标，低／中／高的 MSAA 为 0／2／4 倍；火焰与湿雾使用的独立深度和正在写入的主画面分开。辉光阈值只接受超出普通漫反射亮度的辐射，主要衬托火和倒影。低档关闭 AO 与辉光，但保留统一的输出 pass。最终输出只做一次 AgX 与 sRGB 转换，没有固定调色图片或景深模糊。

高档绘制预算为 8,294,400 像素、DPR 上限为 2，可覆盖 3840 × 2160 的原生画面；中／低档分别为 1,500,000／850,000 像素和 DPR 1.25／1。大视口会按总像素预算缩放。`capture --scale device` 控制 PNG 的浏览器设备像素尺寸，不绕过这些 WebGL 预算；实际尺寸由诊断中的 `drawingWidth` / `drawingHeight` 给出。

## 时间、后台和输入

- 只有主 RAF 推进天气。首帧 delta 为零，长帧最多推进 0.1 秒，恢复时不追赶后台时间。
- 提交完整画面后创建 WebGL 2 fence 并 flush。后续 RAF 用零超时查询；GPU 未完成时仍更新轻量 CPU 状态和声音，推迟下一次 GPU 提交。最多保留一次未完成提交，避免软件 GPU 排队。
- 画质、天候、火势、添柴、降水量、窗口变化和重置先改状态，再把静态重绘合并到一个 RAF；若 GPU 忙，则安排下一次重试，不推进模拟时间。输入处理器不直接提交画面。
- 用户暂停、设置弹窗、页面隐藏、上下文丢失是独立的画面暂停原因。声音保留用户开启意图；设置弹窗允许试听音量，其他暂停原因暂停 AudioContext。
- 减少动态效果模式从静止开始。取消该偏好不自动取消用户暂停；主动起风或继续才恢复。
- 初次与恢复后的首帧已直接提交，随后不重复安排同一静止画面。

`frames` 只计入实际 GPU 提交，`renderedElapsed` 记录最后一幅已提交画面的模拟时刻。`lastRenderCpuMs` 是 CPU 提交耗时，不是 GPU 完成时间。`calls` 和 `triangles` 包括该提交中的阴影、嵌套反射和后处理；缓存更新帧与复用帧应分开比较。`canopyBakes`、两种阴影更新计数／时刻、湿雾尺寸／步数和反射计数用于核查缓存行为，不能直接当作实机 FPS。

## 声音

用户点击「听声」后才创建 AudioContext、生成 PCM 和 9 个循环声源：两层风、左右远雨、湿石滴水、棚沿滴水、柴火裂响、余烬气流与落雪拂过棚布的轻声。不同长度与种子避免同时循环；没有逐雨滴创建节点、独立计时器或录音资源。

低风使用周期稳态滤波，远雨使用着色宽频分布，火声由保留静默间隙的不规则短瞬态组成。小雨减少连续雨幕和落滴速率，雪使用柔和的独立声层并关闭液态雨层；火声读取实际火焰和余烬强度。增益、声像与速率随共享状态平滑更新，通常限制为约 20 Hz，显式天气或火况变化可立即更新。

另外预生成三种滚雷与冷热两种添柴 PCM。`AmbienceEventCursor` 只在共享模拟时间越过声传播延迟时触发雷声，以距离调整滤波、强度和声像；不会提前在仍运行的音频时钟上安排雷声，因而冻结的画面不会在设置内继续推进一次尚未到达的雷。添柴以事件身份触发木质碰撞与可选炭火碎响。最多同时存在两段雷声和两段添柴声，结束时断开节点，重复输入复用有限声部。

静音、暂停、重置及释放取消活动短事件，漏听或晚开启不补播过去事件。循环层初始为静音，关闭声场期间直接安装当前参数，避免首次开启漏出旧雨声或已熄的火声。总音量和归零的声音层平滑衰减后精确到零；相同目标不会逐帧把归零时刻推后。`ProceduralAmbience` 保留用户开启意图，合并异步 resume/suspend 并处理释放期间的竞争。诊断包含循环／事件声源数、节点数、累计雷声与添柴事件和并发峰值；实际 PCM 信号验收记录见 [浏览器验收](browser-validation.md)。

## 恢复与释放

应用的 WebGL 恢复监听早于 Three.js，因此需要等下一个任务再重建 GPU 缓存，微任务不够。恢复过程重建接触遮蔽、静止姿态树冠场和局部环境，遵循启动时的捕获顺序；随后恢复活动风姿态，重置独立深度／AO与后处理／湿雾目标，使方向光和两盏火光阴影、浅水反射失效，并重新上传保留在 CPU 的程序材质数据。随后的静止重绘捕获同一模拟时刻；浏览器验收需对比恢复前后的画面与时间状态。

场景统一收集并释放不同的 Mesh/Points 几何与材质；土壤、树皮材质的释放事件销毁各自程序纹理，树林释放共享的深度／距离阴影材质，场景中的点光源同步释放阴影资源。水模块只释放自己拥有的反射目标，其几何和材质仍由场景释放，避免重复调用 `Reflector.dispose()`。Renderer 释放天空、局部环境目标、方向光阴影、接触遮蔽、树冠场、独立深度／AO、后处理和 WebGL 实例；湿雾 pass 拥有并释放其 3D 噪声、目标和 shader。

上下文丢失清除旧 fence 引用；正常退出删除有效 fence。退出同时取消活动／静态 RAF、事件监听、观察器和提示计时器，并停止音频源、断开节点及关闭 AudioContext。

## 扩展另一个地方

先建立具体的视点、天气、远近关系和声音。新目录实现 `LandscapeScene`，提供完整资源所有权、横竖屏相机、质量更新与必要的缓存失效接口，再在注册表加入元数据。只有作品数量需要时才加入选择界面。

当前优先级仍是同一处林间风景在不同天候和火况下的视觉与听感验收，以及真实设备上的启动、帧耗时和发热。不要为尚不存在的场景建立编辑器、账号或通用玩法系统。
