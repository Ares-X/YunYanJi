# 程序化诗境框架

## 这一阶段的范围

先建立一处可以完整运行、暂停、恢复和释放的诗境，再扩展作品集。活动首景为 `createSnowWorld`：从雪岸的人眼高度观看针叶林与蜿蜒溪流，以风托雪片演绎「未若柳絮因风起」。首景已从庭院试作调整为连续雪谷；当前版本仍待视觉验收，不声称复原谢氏宅第，也不声称已经达到摄影写实。

几何、表面、针叶透明轮廓、倒影、环境光和声音均由运行时程序生成。当前首景没有建筑、局部暖灯或自由行走系统。

## 子系统契约

| 模块 | 拥有的状态 | 不应承担的职责 |
| --- | --- | --- |
| `WeatherSimulation` | 活跃时间、阵风、雪量 | Three.js 对象、浏览器权限、DOM |
| `PoemScene` | 自己创建的几何、材质、粒子和场景缓存 | 全局循环、窗口事件、AudioContext |
| `WorldRenderer` | Renderer、相机、光照、雾、环境图、近地遮蔽、后处理与帧诊断 | 诗文内容、用户声音意图 |
| `WinterAtmosphere` | 程序天空、云、太阳方向与环境捕获状态 | 场景几何、窗口事件、独立时钟 |
| `WinterPostProcessing` | HDR 目标及深度、GTAO、去噪、输出转换 | 场景装配、天气推进、预制素材 |
| `SnowStream` | Reflector、反射缓存、解析水面与失效状态 | 独立计时器、窗口事件、全局渲染循环 |
| `ProceduralAmbience` | 懒创建的 AudioContext、图、播放意图 | 浏览器 visibility 监听、场景几何 |
| `Shell` | DOM、原文与设置对话框 | 绘制循环、材质生成、音频 DSP |
| `main` | 输入映射、组合暂停原因、资源装配 | 各诗境具体几何和声音采样算法 |

长度以米、时间以秒计，+Y 向上。横屏和竖屏各有相机位置与目标点；拖动改变受控视线和少量位置偏移。相机不是轨道式俯视模型，也没有碰撞或自由行走，因此没有引入物理引擎。

## 程序生成与缓存

1. 使用 `seed + namespace` 为每个系统生成独立随机序列。
2. 初次进入场景时生成几何、针叶数据与粒子分布。静态几何按材质实例、投影属性和图层合并，减少绘制调用；水面与粒子单独保留。当前树干、枝条、倒木和地形不随时间变形，因此方向光阴影可在首次绘制、画质设置及上下文恢复后更新并缓存。将来增加树枝动画时，必须同步使阴影失效，不能沿用静态缓存假设。
3. 材质函数以米制表面坐标解析计算颜色、粗糙度与微表面变化，细节随移动网格一起运动；高度与接地计算仍使用世界坐标。颜色在 Three.js 的线性光照流程中运算，输出统一做色调映射与色彩转换。
4. `forestNeedles` 将算法生成的细针和小枝写入 512² RGBA 数据，颜色标记为 sRGB，透明区域保持空缺；弯曲交叉曲面承载该分布，使用 alpha test 与可用的多重采样覆盖。纹理按种子缓存、按材质引用计数，最后一个引用释放时销毁。它不是下载图片或固定像素数组。
5. `WinterAtmosphere` 基于 Three.js 解析天空实现大气散射与程序云。PMREM 在启动／上下文恢复时捕获该天空；捕获时暂时隐藏小太阳盘，避免环境图热像素。方向光与天空太阳共用方向。环境图由 Renderer 释放。
6. 启动／上下文恢复时，从近地几何下方捕获随高度衰减的遮蔽场，模糊并缓存。接收权重写入顶点属性，仅让不投射、但接收阴影的地面采样它；雪帽不会采样自身投影而变黑。该场仍是固定世界高度范围内的弱辅助，不能准确表示整片起伏雪岸，也不能替代全局光照。画质切换和逐帧更新不重新捕获。
7. 溪面使用 Three.js `Reflector` 捕获当前场景的平面倒影，再解析计算随时间流动的噪声导数、岸边薄冰与霜。低／中／高画质分别使用 256²／384²／512² 反射目标。目标与主场景保持线性 HDR，最终显示转换由统一输出 pass 完成；反射不依赖预制图像。
8. 显式开启声音时才生成 PCM 与音频图；更新只调整平滑参数。风声使用周期稳态滤波，避免循环尾部被人为抹平而出现周期性变弱；两路不同长度的风声和一路不规则木质共振构成三个循环声源。共享风场同时驱动滤波、声像与播放速率。

溪面读取同一份 `EnvironmentSnapshot`，没有第二套时钟。视角静止时，反射按模拟时间最多每 1/8 秒刷新一次，其余帧复用缓存；相机、投影或溪面变换变化会提前刷新。雪量变化、时间回退、反射尺寸变化和 `invalidateRenderCaches()` 会让下一次绘制重新捕获。暂停时模拟时间不推进，静止画面不会为反射继续计时。

`WorldRenderer` 在实际提交一次可见帧前统一重置统计，`calls`／`triangles` 包含该帧的阴影、嵌套反射和后处理绘制；GPU 忙时保留上次提交的统计，并累计 `deferredFrames`。动画循环的 `frames` 仅计入成功提交，`lastRenderCpuMs` 表示 CPU 提交耗时，不是 GPU 完成耗时。场景另提供 `reflectionUpdates`／`reflectionSize` 与生成树数量，后处理提供 AO 开关和尺寸。比较开销时应区分缓存刷新帧与复用帧，不能把这些指标直接等同于真实设备 FPS。

当前逐像素材质计算、针叶覆盖和大规模几何的成本仍需在实机上评估。是否增加更多运行时烘焙、分帧生成或 Worker，应根据实际瓶颈决定。

## 深度、遮蔽与颜色

所有画质共用 `RenderPass → 可选 GTAO → OutputPass`。主画面写入 HalfFloat HDR 目标与 24 位深度纹理；低／中／高档的 MSAA 为 0／2／4 倍。低档关闭 GTAO，但保留输出 pass，避免直接画屏幕与 HDR 路径的雾色处理顺序不同。

中高档的 GTAO 复用主画面 DepthTexture，并由深度重建法线，不额外重画整片森林。AO 与边缘保持去噪采用半宽、半高目标，即约四分之一像素数；中／高档分别使用 6／12 个 AO 样本。去噪噪声同样由代码生成并保留 CPU 数据。该效果处理局部接触，不是全局光照，也不会恢复屏幕外的遮挡者。

反射拥有独立目标，完成后恢复主目标；主渲染结束时解析 MSAA 深度，再供 AO 采样。Three.js 在普通离屏目标上保持线性工作色彩空间，不执行屏幕色调映射；最终 `OutputPass` 执行一次 ACES 与 sRGB 转换。当前没有景深、bloom 或覆盖画面的调色滤镜。

## 时间与暂停

- `requestAnimationFrame` 负责调度，模拟按秒推进；活动循环中的天气、声音和轻量 CPU 场景状态继续更新，即使当前不能提交新的 GPU 画面。
- 首帧 delta 为零；长帧最大推进 0.1 秒，避免页面恢复时跳变。
- 完整后处理提交后创建 WebGL 2 fence 并 flush；下一次绘制用零超时查询其状态，上一帧尚未完成就推迟提交，后续 RAF 使用最新状态重试。可见画面最多保留一次尚未完成的提交，不通过阻塞等待 GPU 追上 CPU；这一机制限制排队，不降低单帧本身的渲染成本。
- 暂停、重置、画质、雪量与窗口尺寸先更新状态，静止画面的重绘合并到一个待执行 RAF；若 GPU 仍忙就继续安排一次重试，不推进模拟时间。活动动画循环负责自己的重绘。输入事件处理器不直接提交整幅画面，恢复播放、上下文丢失和退出时会取消待执行的静态帧。
- 用户暂停、页面隐藏、对话框打开、上下文丢失采用组合条件；任何一项成立就暂停画面。声音使用独立组合条件：设置弹窗允许试听已开启的声音，诗文弹窗仍暂停声音。
- 恢复时清空上一帧时间戳，不追赶后台时间。
- 原生 AudioContext 的启用意图与临时暂停状态分离；暂停不覆盖声音开关。
- 用户主动起风可以从静止状态开始体验。
- WebGL 恢复时重建环境光与近地遮蔽，释放并重建后处理目标，标记静态树影更新，并通过场景的 `invalidateRenderCaches()` 使溪面反射在下一次绘制刷新。程序针叶和 AO 噪声保留生成数据供重新上传。
- 应用的恢复监听器先于 Three.js 注册，因此必须等到下一个任务再重建 GPU 缓存。原生事件监听器之间可能执行微任务，仅 `await Promise.resolve()` 无法保证 Three.js 已完成内部恢复；浏览器回归检查会比较静止画面恢复前后的颜色。
- 上下文丢失时清除旧 fence 的引用；应用退出时删除仍属于有效上下文的 fence。恢复后的绘制不会查询旧上下文的同步对象。
- 溪面反射目标由 `disposeTargets()` 释放；其几何与材质由场景遍历统一释放，避免重复调用会同时释放材质的 `Reflector.dispose()`。针叶材质负责归还生成纹理引用；Renderer 另释放环境图、阴影图、近地遮蔽和后处理资源。

## 新增一首诗

1. 校对诗文、出处、季节与所要表现的意象。
2. 在 `scenes/<id>/` 实现 `PoemScene`。模块内部应显式拥有生成的资源，并完整 `dispose()`；有生成缓存时实现可选的 `invalidateRenderCaches()`，需要观测场景开销时提供 `diagnostics()`。
3. 提供适配横竖屏的小范围相机位置与目标点。
4. 在 `registry.ts` 注册内容和创建函数。作品数量增加后再设计选择界面。
5. 让风、雨或其他声音读取共同的环境状态；需要新的状态字段时扩展 `core/types.ts`。
6. 给生成器添加有价值的边界测试，并在浏览器中验证真实画面和声音状态。

## 后续美术优先级

- 继续校正树冠与针叶的自然疏密、枝上承雪关系和不同树龄的形态，避免重复层架。
- 检查雪岸、岩石与倒木的埋入、湿润边界和米／厘米尺度细节，避免浮空、尖锐雪边与均匀噪声。
- 用侧光、真实遮挡和远近林层形成纵深，按实际截图校准冷暖、曝光、反射与雾，不用景深或 bloom 掩盖形体问题。
- 分别检查横竖屏和拖动后的视角，并由用户验收写实程度与诗意。
- 在真实手机上测量帧耗时、发热、启动时间，决定是否增加自动画质适配。
- 用真实耳机／扬声器检查风声循环、频谱、响度与画面的一致性。

这些是后续可独立推进的工作，不应在首个框架中提前加入账号、社交、计分或通用编辑器。
