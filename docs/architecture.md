# 架构

## 范围与模块边界

当前注册的场景是 `rainfire`，由 `createRainfireWorld` 创建。项目从古诗雪景转向独处的自然风景，复用时间、生成树木、GPU 生命周期和音频管理，不继续扩展原有诗境选目。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `WeatherSimulation` | 种子、模拟时间、阵风和雨量 | Three.js 对象、DOM 和浏览器权限 |
| `LandscapeScene` | 自有几何、材质、相机基准、更新、画质和释放 | 全局事件、音频授权和动画循环 |
| `WorldRenderer` | 相机、主灯光、环境、画质、GPU 提交与恢复 | 推进天气时间、创建音频节点 |
| `RainAtmosphere` | 解析阴云、冷天光和天空背景 | 独立计时、固定天空图片 |
| `LandscapePostProcessing` | 线性 HDR、深度、接触 AO、火光辉光与输出转换 | 场景生成、调度 RAF |
| `ProceduralAmbience` | 用户开启意图、AudioContext、暂停与释放 | 直接读取 DOM 和推进天气 |
| `createAmbienceGraph` | 合成声源、空间混音、参数平滑 | 新建计时器、下载录音 |
| `Shell` / `main` | 原生界面、交互、组合暂停原因和系统装配 | 具体地形及合成声音算法 |

米与秒是统一单位，+Y 向上。`EnvironmentSnapshot.precipitation` 为 0–1 雨量；视觉和声音读取同一份 `elapsed`、`wind` 和 `gust`。各系统使用独立种子命名空间，新增一个声音随机数不会改变树的位置。

横屏、竖屏各有相机位置与目标。拖动改变受限视线并附带很小的位置偏移，不是轨道俯视，也没有自由行走或碰撞模拟。

## 雨夜场景

| 文件 | 职责 |
| --- | --- |
| `createRainfireWorld.ts` | 装配场景、树木层次、横竖屏相机与统一释放 |
| `rainLandscape.ts` | 连续高度场、湿地凹陷、火旁土丘、石块和木棚，以及共享的棚下范围 |
| `rainMaterials.ts` | 米制解析土、石、树皮与木材纹理、粗糙度和微表面法线 |
| `campfire.ts` | 劈柴、炭床、灰与石圈，三维 raymarch 火焰／烟、火星及局部暖光 |
| `rainParticles.ts` | 雨线、落点与风驱动，读取与棚一致的遮挡范围 |
| `wetGround.ts` | 浅水平面、真实场景倒影、细波与雨圈、反射缓存和目标所有权 |

`scenes/snow/forestTrees.ts` 的程序树木生成器增加显式 `snowCover: false` 选项，保留默认雪景行为。雨林复用枝系与运行时针叶覆盖数据，但不创建雪面。旧雪景未注册到活动场景列表。

静态树木按材质和绘制属性合并，保留针叶覆盖需要的 UV。火木材的 shader 使用局部坐标和自定义属性，火组不参与普通静态合并。

## 资源与运行时生成

初次进入时生成地形、树木、石块、木材、粒子分布和针叶数据，逐帧只更新必要参数。所有视觉资源来自计算；没有贴图文件、HDRI、模型文件或嵌入的图像数据。

针叶生成器将小枝和细针栅格化为 512² RGBA 数据。曲面承载覆盖分布，通过 alpha test 和可用的多重采样处理空隙。数据按种子缓存，材质按引用释放；最后一份引用释放时销毁纹理。

`RainAtmosphere` 计算多层缓慢移动的阴云。PMREM 在启动和上下文恢复时捕获同一个初始时刻的程序天空，供材质接受冷色环境光；捕获后恢复当前天空时间，避免运行中的冻结画面在恢复后突然改变间接照明。局部火光位置保持固定，亮度由模拟时间缓慢和快速分量共同调节。它不对整片森林做昂贵的六面点光源阴影。

当前地形和树木不随时间变形，方向光阴影可缓存到首次绘制、画质变化或上下文恢复时更新。以后若加入动态枝叶或移动光源，需要同步改变缓存策略。

启动和恢复时另烘焙一次近地接触遮蔽。该场只为接收地面补充有限高度范围内的接触感；它不是全局光照。带 alpha 纹理的针叶片不参与此捕获，避免把透明承载面烘焙成矩形黑块。

## 水面反射

浅水由水平反射面与同一连续地形相交，地形定义露出的水域边缘和火旁高地。水网格以实际地形差计算厘米级深度，浅岸平滑混入底土，避免一条生硬的镜面边界。Three.js `Reflector` 捕获真实场景；火焰和雨线使用相同的时间与相机协议，因此倒影来自当前场景而非另一份手画效果。

低／中／高档分别使用 256²／384²／512² 目标。视角静止时，反射按模拟时间最多每 1/8 秒捕获一次，其他帧复用。相机、投影、水面变换、雨量、时间回退、目标尺寸与上下文恢复会让缓存失效。暂停不推进模拟时间，也不为反射单独设时钟。

反射在线性 HDR 空间内完成，目标结束后恢复主渲染目标。波纹只产生细微的法线与采样扰动；棚下范围与雨线共享，不能在同一位置一边遮雨一边持续出现雨圈。

## 深度、后处理与颜色

所有画质使用同一线性颜色路径：

`RenderPass → 可选 GTAO → 可选 HDR bloom → OutputPass`

主画面写入 HalfFloat HDR 与 24 位深度纹理。低／中／高的 MSAA 为 0／2／4 倍。中高档 GTAO 复用主画面深度重建法线，不重新绘制整片森林；AO 与边缘保持去噪在半宽半高目标运行，中高档分别使用 6／12 个 AO 样本。

辉光阈值只接受超出普通漫反射亮度的辐射，主要衬托火和倒影。低档关闭 AO 与辉光，但保留统一的输出 pass。最终输出只做一次 ACES 与 sRGB 转换，没有固定调色图片或景深模糊。

## 时间、后台和输入

- 只有主 RAF 推进天气。首帧 delta 为零，长帧最多推进 0.1 秒，恢复时不追赶后台时间。
- 提交完整画面后创建 WebGL 2 fence 并 flush。后续 RAF 用零超时查询；GPU 未完成时仍更新轻量 CPU 状态和声音，推迟下一次 GPU 提交。最多保留一次未完成提交，避免软件 GPU 排队。
- 画质、雨量、窗口变化和重置先改状态，再把静态重绘合并到一个 RAF；若 GPU 忙，则安排下一次重试，不推进模拟时间。输入处理器不直接提交画面。
- 用户暂停、设置弹窗、页面隐藏、上下文丢失是独立的画面暂停原因。声音保留用户开启意图；设置弹窗允许试听音量，其他暂停原因暂停 AudioContext。
- 减少动态效果模式从静止开始。取消该偏好不自动取消用户暂停；主动起风或继续才恢复。
- 初次与恢复后的首帧已直接提交，随后不重复安排同一静止画面。

`frames` 只计入实际 GPU 提交，`renderedElapsed` 记录最后一幅已提交画面的模拟时刻。`lastRenderCpuMs` 是 CPU 提交耗时，不是 GPU 完成时间。`calls` 和 `triangles` 包括该提交中的阴影、嵌套反射和后处理；缓存更新帧与复用帧应分开比较。诊断数据不能直接当作实机 FPS。

## 声音

用户主动开启后才生成 PCM 和 8 个复用声源：两层风、左右远雨、湿石滴水、棚沿滴水、柴火裂响和余烬气流。不同长度和种子避免所有层同时循环。没有事件音频节点逐滴创建，也没有独立计时器。

低风使用周期稳态滤波，远雨使用着色宽频分布。火声由不规则短瞬态组成，保留较长静默区段。以共享天气更新增益、声像与风声速率；参数约 20 Hz 平滑，不依赖视频帧率。

总音量和静音门先平滑衰减，再精确到零。暂停 AudioContext，不覆盖用户的启用意图。`ProceduralAmbience` 合并异步 resume/suspend，处理快速开关和释放期间的竞争。

## 恢复与释放

应用的 WebGL 恢复监听早于 Three.js，因此需要等下一个任务再重建 GPU 缓存，微任务不够。恢复过程重建环境光和接触遮蔽、重置后处理目标、刷新静态阴影与浅水反射，并重用保留在 CPU 的生成针叶数据。浏览器测试对比同一静止画面恢复前后的颜色。

场景统一收集并释放不同的 Mesh/Points 几何与材质；针叶材质归还缓存纹理引用。水模块只释放自己拥有的反射目标，其几何和材质仍由场景释放，避免重复调用 `Reflector.dispose()`。Renderer 释放天空、环境目标、方向光阴影、接触遮蔽、后处理和 WebGL 实例。

上下文丢失清除旧 fence 引用；正常退出删除有效 fence。退出同时取消活动／静态 RAF、事件监听、观察器和提示计时器，并停止音频源、断开节点及关闭 AudioContext。

## 扩展另一个地方

先建立具体的视点、天气、远近关系和声音。新目录实现 `LandscapeScene`，提供完整资源所有权、横竖屏相机、质量更新与必要的缓存失效接口，再在注册表加入元数据。只有作品数量需要时才加入选择界面。

当前优先级仍是第一处雨夜的视觉与听感验收，以及真实设备上的启动、帧耗时和发热。不要为尚不存在的场景建立编辑器、账号或通用玩法系统。
