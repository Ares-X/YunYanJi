# 架构

## 范围与模块边界

当前注册的场景是 `rainfire`，由 `createRainfireWorld` 创建。项目从古诗雪景转向独处的自然风景，复用时间、GPU 生命周期和音频管理，雨林与地表使用独立生成器，不继续扩展原有诗境选目。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `WeatherSimulation` | 种子、模拟时间、阵风和雨量 | Three.js 对象、DOM 和浏览器权限 |
| `LandscapeScene` | 自有几何、材质、相机基准、更新、画质和释放 | 全局事件、音频授权和动画循环 |
| `WorldRenderer` | 相机、主灯光、环境、画质、GPU 提交与恢复 | 推进天气时间、创建音频节点 |
| `RainAtmosphere` | 解析阴云、冷天光和天空背景 | 独立计时、固定天空图片 |
| `GroundContactShadows` | 共享的近地接触遮蔽捕获、接收标记与缓存 | 全局光照和动态物体的逐帧阴影 |
| `CanopyLightField` | 静止姿态的树冠／布棚覆盖，供间接照明与空气散射共同采样 | 逐叶动态阴影、直接光衰减和全局光照求解 |
| `ForestAtmospherePass` | 根据主画面深度积分风驱动湿雾，采样树冠场与方向／火光阴影 | 重新绘制场景深度、独立推进时间 |
| `LandscapePostProcessing` | 线性 HDR、共享深度、原位 AO、湿雾、火光辉光与输出转换 | 场景生成、调度 RAF |
| `ProceduralAmbience` | 用户开启意图、AudioContext、暂停与释放 | 直接读取 DOM 和推进天气 |
| `createAmbienceGraph` | 合成声源、空间混音、参数平滑 | 新建计时器、下载录音 |
| `Shell` / `main` | 原生界面、交互、组合暂停原因和系统装配 | 具体地形及合成声音算法 |

米与秒是统一单位，+Y 向上。`EnvironmentSnapshot.precipitation` 为 0–1 雨量；视觉和声音读取同一份 `elapsed`、`wind` 和 `gust`。各系统使用独立种子命名空间，新增一个声音随机数不会改变树的位置。

横屏、竖屏各有相机位置与目标。拖动改变受限视线并附带很小的位置偏移，不是轨道俯视，也没有自由行走或碰撞模拟。

## 雨夜场景

| 文件 | 职责 |
| --- | --- |
| `createRainfireWorld.ts` | 装配地形、树林、地表散落物与天气效果，管理横竖屏相机和统一释放 |
| `rainLandscape.ts` | 连续高度场、破碎积水低洼、火旁高地、石块、带下垂与拉绳的布棚，以及共享的棚下范围 |
| `livingForest.ts` | 成熟树干、根颈、曲线分枝、折面叶片与中远景树群，按材质及阴影范围合批 |
| `forestWind.ts` | 根部固定的树干弯曲、叶柄局部转动，以及主画面、深度和点光阴影共用的形变 |
| `barkSurface.ts` | 按物理尺度生成树皮鳞片、裂隙和苔色，共源颜色／法线／粗糙度数据 |
| `earthMaterials.ts` | 程序土壤微结构、关联材质数据与米制世界坐标采样，区分土壤和局部湿泥膜 |
| `forestEcology.ts` | 同一种子下的腐殖层、踩踏路径、根部影响与苔丛分布，供地表材质和几何共同采样 |
| `forestDebris.ts` | 卷曲腐叶、断枝、细砾、苔丛、蕨叶和低矮灌丛几何，按材质合批 |
| `rainMaterials.ts` | 石块、木材等表面的米制解析纹理、粗糙度和微表面法线 |
| `fireIllumination.ts` | 绝对模拟时间与种子驱动的统一燃烧包络，原位更新位置、能量、颜色及烟／炭参数 |
| `campfire.ts` | 劈柴、炭床、灰与石圈，三维 raymarch 火舌／受光烟、冷却余烬，将共享燃烧状态绑定到材质与灯光 |
| `rainParticles.ts` | 雨线、落点与风驱动，读取与棚一致的遮挡范围 |
| `wetGround.ts` | 浅水平面、真实场景倒影、Fresnel 与水深吸收的透明合成、细波与雨圈、反射缓存和目标所有权 |

当前树林由 `livingForest.ts` 独立生成。树干和枝条沿曲线生长，叶子是有折角与弯曲的几何；近处与远处分别合批，让近处投影不必绘制整片远林。旧雪景的生成器与针叶覆盖数据仍留在归档模块，未参与活动雨林，也未注册为可选场景。

`forestWind.ts` 使用每棵树的根部／高度和每片叶子的附着位置，保持根部固定并随高度增加弯曲，叶片绕叶柄转动。主材质、`customDepthMaterial` 和 `customDistanceMaterial` 注入同一形变，主画面的法线也随之调整；方向光与点光阴影不会沿用另一种静止轮廓。时间直接读取 `EnvironmentSnapshot.elapsed`，减少动态效果模式的风形变强度为零。包围体为有界摆动留出余量，避免边缘裁剪。

树木、地表散落物和静态环境物体各自按材质、投影与接收属性合批。火组不参加通用静态合并；木柴由火模块单独合并，通过 `aFuelPosition`、`aFuelNormal`、`aFuelRadius` 和 `aFuelIdentity` 保留每段柴的原始局部坐标、法线、半径与身份，避免合批后木纹、年轮和炭化范围错位。

## 资源与运行时生成

初次进入时生成地形、树木、石块、木柴、地表散落物、粒子分布以及土壤和树皮数据，逐帧只更新必要参数。所有视觉资源来自计算；不加载固定图像贴图、HDRI、模型文件或嵌入的图像数据。程序生成的 `DataTexture`、环境纹理和渲染目标仍是正常使用的 GPU 纹理资源。

土壤把淤泥、矿物颗粒和有机残留生成到同一组微结构中，再导出关联的颜色、法线与表面数据；米制采样和不同方向的混合降低平铺痕迹。湿度、近水高度、腐叶和苔丛共同控制泥面薄水膜，水膜沿同一地形法线接受高光，不用整体提亮土壤颜色表示潮湿。树皮由错落鳞片、剥蚀和裂隙高度生成关联颜色、法线和粗糙度，湿流槽较暗且较光滑。两者都使用运行时 `DataTexture` 和 mipmap，不从磁盘载入图像。纹理由对应材质持有，随材质释放；保留的 CPU 数据可供上下文恢复重新上传。

`forestEcology.ts` 在同一种子下生成一致的 224² 分布网格，RGBA 分别表示腐殖覆盖、踩踏程度、根部影响和苔丛覆盖。CPU 双线性采样用于选择腐叶、碎枝、砾石、苔丛与蕨类位置；GPU 采样同一分布定义的运行时纹理，调整泥地色泽与细节。根部与倒木附近的腐殖区、通向火堆的踩踏区因此与表面着色有关联，而不是各系统独立撒点。该分布是场景生成规则，没有模拟植物生长、侵蚀或水流。

林下另有沿不对称土岸布置的低矮木质灌丛与蕨类，使用地形高度安放并避开积水，冠下附带腐叶与断枝。岸边残叶按实际高度寻找水线，形成小片堆积。它们复用地表叶片、木质与砾石批次，没有引入外部植物模型。

## 光场、火光与阴影

`RainAtmosphere` 计算多层缓慢移动的阴云。PMREM 在启动和上下文恢复时捕获同一个初始时刻的程序天空，供材质接受灰冷环境光；捕获后恢复当前天空时间，避免运行中的冻结画面在恢复后突然改变间接照明。方向光与程序天空共享来光方向。

`CanopyLightField` 从上方捕获静止姿态的树冠、树干和布棚，按覆盖率累积到 512² 目标并模糊，得到宽尺度的遮天分布。覆盖场仅在启动和环境重建时生成，不追踪每片摆动叶子。它在材质中只调节间接漫反射与间接镜面反射，叶片使用较弱权重；不会再乘一次直接太阳光或直接火光。湿雾也采样这个场，因此空气与地表共享开敞／林冠覆盖关系。该场是二维覆盖近似，不是三维可见性场或全局光照解算。

`fireIllumination.ts` 使用连续的时间噪声组合缓慢燃料释放、气流和小尺度波动。它不推进独立 RNG 或依赖帧间滤波，同一种子在同一模拟时刻得到同一组数值。稳定输出对象同时驱动火舌高度与热量、主灯厘米级位置变化、强度与线性颜色、炭床和木柴裂缝；烟接受这盏灯随距离衰减的照明。`Campfire.light` 向场景暴露实际灯光，空气散射读取其世界位置、颜色与强度，不另造一套火光闪烁。

中高画质开启火旁点光源阴影，仅捕获指定图层、有限距离内的遮挡物；低画质关闭。木柴、石圈、近树和布棚可以遮挡火光，远林不加入这次六面捕获。地形与柴木不移动，但枝叶形变和火光位置会改变阴影：`WorldRenderer` 按模拟时间分别以最多 6 Hz 更新方向光阴影、10 Hz 更新火光阴影，每盏灯独立设置失效标记，避免每次火光更新都重画远林。

首次渲染、时间回退、画质切换和上下文恢复会使相应阴影缓存失效。静止重绘的 `delta === 0` 若对应时刻尚未捕获，则补一次该精确时刻的阴影；再次绘制同一暂停时刻会复用。刷新频率是缓存策略，不是测得的设备帧率，也不表示实现了动态面光源或全局照明。

`render/GroundContactShadows.ts` 是场景间共享的近地接触遮蔽实现，启动和恢复时各烘焙一次。该场只为接收地面补充有限高度范围内的接触感；它不是全局光照。接收权重写入几何属性，保留投影与接收物共享材质时的差别；粒子和带 alpha 裁剪贴图的承载片不参与简化捕获，避免产生矩形黑块。厘米级散落物主要由屏幕空间 AO 补充接触，不逐片增加阴影绘制。

## 水面反射

浅水由水平反射面与同一连续地形相交，地形定义露出的水域边缘和火旁高地。水床平滑混向约 2–3 cm 深的浅洼，低泥脊打断部分水面，岸沿缓缓接回湿土；不从原地面固定挖出深盆。水网格以实际地形差计算深度，水线处渐隐。

Three.js `Reflector` 捕获真实场景；火焰和雨线使用相同的时间与相机协议，因此倒影来自当前场景而非另一份手画效果。水材质用 Fresnel 调节随视角变化的反射，以水深吸收控制透明层的颜色和不透明度，使下方实际渲染的泥底可见。倒影、浅水颜色与底土由透明合成叠加，水面不再完全替换泥地。

低／中／高档分别使用 256²／384²／512² 目标。视角静止时，反射按模拟时间最多每 1/8 秒捕获一次，其他帧复用。相机、投影、水面变换、雨量、时间回退、目标尺寸与上下文恢复会让缓存失效。暂停转入精确时刻 T 时，若缓存不是 T，则补一次 T 的倒影；后续同一静止画面不重复捕获。暂停不推进模拟时间，也不为反射单独设时钟。

反射在线性 HDR 空间内完成，目标结束后恢复主渲染目标。波纹只产生细微的法线与采样扰动；棚下范围与雨线共享，不能在同一位置一边遮雨一边持续出现雨圈。

## 深度、后处理与颜色

所有画质使用同一线性颜色路径：

`RenderPass → 可选原位 GTAO → ForestAtmospherePass → 可选 HDR bloom → OutputPass`

主画面写入 HalfFloat HDR 与 24 位深度纹理。低／中／高的 MSAA 为 0／2／4 倍。中高档 GTAO 复用主画面深度重建法线，不重新绘制整片森林；AO 与边缘保持去噪在半宽半高目标运行，中高档分别使用 6／12 个 AO 样本。AO 使用固定功能混合原位乘入主画面颜色，不交换 composer 缓冲，也不采样正在写入的颜色附件；后续湿雾因而拿到与主画面颜色配对的真实深度，避免只复制颜色后误读另一缓冲的空深度。

`ForestAtmospherePass` 沿视线积分单次散射和透射率，以主画面深度截断积分，使用程序 3D 噪声形成风驱动的近地湿雾。中高档在半宽半高目标使用 18／28 个样本，低档在宽高各 35% 的目标使用 10 个样本。靠近相机的采样较密，重建时用深度差约束邻近样本，减少远处亮雾污染近树边缘。中高档直接采样已有方向光与火光阴影纹理；低档保留覆盖场与深度积分，省略逐样本阴影查询。最后在线性空间以「表面颜色 × 透射率 + 散射光」合成。

场景自身只保留较轻的远距雾，也会进入浅水反射；依赖当前视线的湿雾后处理只在最终画面执行一次，没有为每次反射另外计算一套体积雾。该实现不是多次散射、完整水汽模拟或光线追踪。

辉光阈值只接受超出普通漫反射亮度的辐射，主要衬托火和倒影。低档关闭 AO 与辉光，但保留统一的输出 pass。最终输出只做一次 ACES 与 sRGB 转换，没有固定调色图片或景深模糊。

## 时间、后台和输入

- 只有主 RAF 推进天气。首帧 delta 为零，长帧最多推进 0.1 秒，恢复时不追赶后台时间。
- 提交完整画面后创建 WebGL 2 fence 并 flush。后续 RAF 用零超时查询；GPU 未完成时仍更新轻量 CPU 状态和声音，推迟下一次 GPU 提交。最多保留一次未完成提交，避免软件 GPU 排队。
- 画质、雨量、窗口变化和重置先改状态，再把静态重绘合并到一个 RAF；若 GPU 忙，则安排下一次重试，不推进模拟时间。输入处理器不直接提交画面。
- 用户暂停、设置弹窗、页面隐藏、上下文丢失是独立的画面暂停原因。声音保留用户开启意图；设置弹窗允许试听音量，其他暂停原因暂停 AudioContext。
- 减少动态效果模式从静止开始。取消该偏好不自动取消用户暂停；主动起风或继续才恢复。
- 初次与恢复后的首帧已直接提交，随后不重复安排同一静止画面。

`frames` 只计入实际 GPU 提交，`renderedElapsed` 记录最后一幅已提交画面的模拟时刻。`lastRenderCpuMs` 是 CPU 提交耗时，不是 GPU 完成时间。`calls` 和 `triangles` 包括该提交中的阴影、嵌套反射和后处理；缓存更新帧与复用帧应分开比较。`canopyBakes`、两种阴影更新计数／时刻、湿雾尺寸／步数和反射计数用于核查缓存行为，不能直接当作实机 FPS。

## 声音

用户主动开启后才生成 PCM 和 8 个复用声源：两层风、左右远雨、湿石滴水、棚沿滴水、柴火裂响和余烬气流。不同长度和种子避免所有层同时循环。没有事件音频节点逐滴创建，也没有独立计时器。

低风使用周期稳态滤波，远雨使用着色宽频分布。火声由不规则短瞬态组成，保留较长静默区段。以共享天气更新增益、声像与风声速率；参数约 20 Hz 平滑，不依赖视频帧率。

总音量和静音门先平滑衰减，再精确到零。暂停 AudioContext，不覆盖用户的启用意图。`ProceduralAmbience` 合并异步 resume/suspend，处理快速开关和释放期间的竞争。

## 恢复与释放

应用的 WebGL 恢复监听早于 Three.js，因此需要等下一个任务再重建 GPU 缓存，微任务不够。恢复过程重建环境光、接触遮蔽与静止姿态树冠覆盖场，重置后处理／湿雾目标，使方向光和火光阴影、浅水反射失效，并重新上传保留在 CPU 的程序材质数据。随后的静止重绘捕获同一模拟时刻；浏览器验收需要对比恢复前后的画面与时间状态。

场景统一收集并释放不同的 Mesh/Points 几何与材质；土壤、树皮材质的释放事件销毁各自程序纹理，树林释放共享的深度／距离阴影材质，场景中的点光源同步释放阴影资源。水模块只释放自己拥有的反射目标，其几何和材质仍由场景释放，避免重复调用 `Reflector.dispose()`。Renderer 释放天空、环境目标、方向光阴影、接触遮蔽、树冠覆盖场、后处理与 WebGL 实例；湿雾 pass 拥有并释放其 3D 噪声、目标和 shader。

上下文丢失清除旧 fence 引用；正常退出删除有效 fence。退出同时取消活动／静态 RAF、事件监听、观察器和提示计时器，并停止音频源、断开节点及关闭 AudioContext。

## 扩展另一个地方

先建立具体的视点、天气、远近关系和声音。新目录实现 `LandscapeScene`，提供完整资源所有权、横竖屏相机、质量更新与必要的缓存失效接口，再在注册表加入元数据。只有作品数量需要时才加入选择界面。

当前优先级仍是第一处雨夜的视觉与听感验收，以及真实设备上的启动、帧耗时和发热。不要为尚不存在的场景建立编辑器、账号或通用玩法系统。
