# 云烟集 · YunYanJi

**独处的风景。**

Procedural places to sit with rain, wind and fire.

第一处风景叫「雨歇之前」。在林边的遮雨处，近旁有一堆柴火，湿地映着火光，远处是树林。可以听一场雨，也可以等天晴、看雪落，添一根柴后收起文字，停留一会儿。

项目已从古诗场景转向孤独的自然风景。当前只打磨这一处林间篝火，加入可切换的天气与火势，持续校准空间、材料、火焰和声音；画面与听感仍需实际体验验收，构建和测试通过不代表达到摄影写实。

## 运行

使用 Node.js 24：

```bash
npm ci
npm run dev
```

生产构建与本地预览：

```bash
npm run build
npm run preview
```

Vite 使用相对基础路径，可部署在静态网站子目录。无需后端、账号或 API key。

## 体验

- 拖动画面，向四周看；较大的横向拖动也会带起一阵风。
- 「听声」开启程序合成的风、雨、雷、落雪和柴火声；声音默认关闭，必须主动开启。
- 「天候」选择晴天、阴天、小雨、大雨、暴雨或下雪。面板打开时风景继续变化；「打雷」触发远处闪电，雷声随后到来。「间或雷鸣」控制自动雷电，暴雨默认开启。
- 「火势」可选熄灭、余烬、小火、中火或旺火。「添一根柴」增加可见木柴，并影响烟、火光和声音；余烬可续成小火，熄灭的柴堆添柴后仍需选择火势点燃。
- 「入境」收起文字，「显字」或 Escape 返回。
- 「暂停」同时暂停画面和声音；「继续」、「起风」或「打雷」恢复。暂停时仍可静态预览天气和火势，添柴后继续观看燃烧。
- 「设置」调整雨量或雪量、声音和画质，也可以重看或分享相同种子的风景；晴天和阴天的降水调节不可用。
- 画面获得焦点时，空格起风，P 暂停。系统偏好减少动态效果时，从静止画面开始。

## 全部由代码生成

项目不使用固定贴图、模型、HDRI、天空盒、预录音频、视频或远程字体。树干、枝叶、地形、腐叶、木柴、石块和布棚由种子生成；火焰、雨线、雪花、涟漪和天空由几何与 shader 计算。土壤和树皮的颜色、法线、粗糙度来自运行时生成的关联数据，以 `DataTexture` 等 GPU 纹理供材质采样；环境光和倒影也在运行时捕获到纹理目标。声音通过 Web Audio 播放程序合成的 PCM。

同一种子、操作顺序和模拟时间可以重现风景。通过 `?seed=林间-02` 生成另一处；分享只保留风景种子，不保存当前天气、火况、进度或调试状态。

## 当前实现

| 部分 | 做法 |
| --- | --- |
| 空间 | 连续湿土地形、由空间竞争骨架生成的连续树冠、风化石块、带下垂和拉绳的布棚；树干与叶子随共享风场摆动 |
| 地表 | 近景土壤有真实起伏网格，颜色、细尺度法线和粗糙度由关联数据生成；腐叶、碎枝、细砾与植被按共享分布落在实际表面上 |
| 林下 | 随土岸高度布置的低矮灌丛与蕨类，冠下腐叶和碎枝形成前后遮挡 |
| 火 | 五档火势、有限燃料和四个预分配添柴位置；体积火舌受真实木柴深度遮挡，共享燃烧状态驱动烟、炭、暖光与声音 |
| 天气 | 六种天候联动天空、日光、雾、风与降水；雨线、溅水和涟漪随雨量变化，雪花缓慢飘落，表面形成斑驳薄雪，棚下保持遮蔽 |
| 雷电 | 一次宽闪照亮天空、地表与雾；雷声按距离延迟，开启减少动态效果时保留雷声但抑制闪光 |
| 水 | 厘米级浅积水平缓衔接泥地，按视角与水深混合倒影和可见泥底；缓存反射在暂停时补齐到同一时刻 |
| 光 | 程序阴云先照亮树林，再捕获林内静态环境；树冠覆盖、地面接触与屏幕空间 AO 调节间接照明，受光湿雾连接空间，最后统一输出 HDR 辉光与 AgX 色调映射 |
| 声音 | 9 个循环声源加最多 4 个短事件声源；分层风雨、轻柔落雪、滚雷和冷热添柴声全部由种子合成 PCM |
| 生命周期 | 静止重绘、后台暂停、上下文恢复、画质切换、资源释放 |

主画面、不透明深度、方向光阴影和火光阴影共用枝叶形变。方向光与两处火光阴影分别按模拟时间以 6 Hz／10 Hz 的上限刷新，暂停、画质变化和恢复时处理相应失效。独立不透明深度同时供间接 AO、火焰遮挡和湿雾积分使用；低画质保留深度，省略 AO、辉光与湿雾中的阴影查询，并降低湿雾采样。实际画面与设备表现仍按下方流程验收。

当前的雪是林间篝火内的天气：雪花和向上表面的薄层着色会变化，尚未模拟有厚度的积雪、压痕或完整融雪水流。天气通过实时日光、环境强度及雾调节照明，局部环境探针仍为静态近似。旧雪景模块另保留为已归档的试作，未注册为可选择场景；新增下雪天气没有恢复旧诗境目录。当前树林由 `forestGrowth` 与 `livingForest` 共同生成。

## 本地检查和截图

```bash
npm run check
npx playwright install chromium
npm run capture
npm run test:browser
```

已有 Chrome 时可以直接使用：

```bash
PLAYWRIGHT_CHROMIUM_CHANNEL=chrome npm run capture
```

也可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向现有 Chromium。截图输出到 `test-results/captures/`，不上传或触发 GitHub Actions。先在本地反复看画面，完成一轮修改后再推送一次质量门。

可以通过真实界面控件选择天气、火势和添柴数量，再截图：

```bash
npm run capture -- --weather snow --fire small --wood 2 --panel --output test-results/captures/snow-fire
npm run capture -- --device desktop --weather clear --fire out --output test-results/captures/clear
```

`--weather` 接受 `clear|overcast|drizzle|rain|downpour|snow`，`--fire` 接受 `out|embers|small|steady|roaring`，`--wood` 为 0–4；`--panel` 保留天候面板。加 `--seconds 4` 可检查继续燃烧后的形态。

本地无 GPU 时可使用默认 SwiftShader；真实设备复核可设置 `PLAYWRIGHT_SOFTWARE_RENDERING=0`，并检查报告中的实际 WebGL renderer。软件截图不能证明手机或电脑的实际帧率。

默认截图按 CSS 像素保存。检查高密度屏幕的实际细节时，使用 `npm run capture -- --device desktop --dpr 2 --scale device --output test-results/captures/retina`，得到 2880 × 1800 的截图。高画质允许最高 2 倍显示像素比，并设有 8,294,400 像素的绘制预算，相当于一幅 3840 × 2160 画面；中低档保持较小预算。截图尺寸与 WebGL 实际绘制尺寸是两回事，应同时查看报告中的 `drawingWidth` / `drawingHeight`。

完整说明见 [浏览器验收](docs/browser-validation.md)。

## 代码结构

```text
src/
  core/       种子、时间、共享天气、雷电与燃料状态
  scenes/     场景协议、注册表、林间篝火与可复用几何
  render/     光照、相机、后处理、画质及 WebGL 生命周期
  audio/      合成算法、声场与 AudioContext 生命周期
  ui/         安静的文字与原生交互
```

开发约束见 [AGENTS.md](AGENTS.md)，具体分工见 [架构](docs/architecture.md)，当前构图与验收目标见 [美术方向](docs/art-direction.md)。

开启 `?debug=1` 才会暴露只用于本地诊断的 `window.__YUNYANJI__`，正常界面没有技术面板。
